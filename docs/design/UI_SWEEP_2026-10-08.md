# UI quality sweep, 8 October 2026

Every screen of the screenshot manifest (`tools/screenshots/screens.cjs`) was captured on the seed profile at
1440 x 900, before and after the sweep, with a presentation check on each page. The complained screens and the
group profile picker were also captured at 1920 x 1080. The rules below are now part of the shared components, so
new screens follow them without screen-specific styles.

## Rules applied to every screen

- **Tiles.** Home pages' tiles use one anatomy and height; labels in Title Case with acronyms kept; linked tiles
  are not underlined; long labels take at most two lines and the counts of a row line up.
- **Titles.** Card titles and tile labels are written in Title Case (the callout names stay as written).
- **Page header.** The title block takes the room left and wraps its description; the page actions stay on the
  right instead of dropping under the title.
- **Tabs.** A tab strip never wraps onto a second row; a long strip scrolls sideways.
- **Toolbars.** Toolbar controls (search, buttons, toggles, check boxes) share one height (40 px) and line up.
- **Tables.** Every column has a header; the actions column reads "Actions". Long header labels wrap between words
  instead of widening the table past its card. A code column keeps its width (the name under the code wraps); a
  two-line text cell is never squeezed to one word per line; codes never break.
- **Values.** Missing amounts show the muted dash; amounts and dates inside texts from the server are formatted
  (PHP 2,500.00, 01-Dec-2027); counts read in the right number everywhere ("1 account", "Showing 1 to 1 of 1
  result"), no more "account(s)"; two values in one cell are a two-line cell, never "a · b".
- **Workflow actions.** The action buttons of a record wrap inside the workflow header; one filled primary action
  per area, the other routes outlined, exclusion and closing outlined red.
- **Names, not codes.** Segment and sales unit of the PR Worklist by name.
